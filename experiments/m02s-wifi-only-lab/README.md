# M02S v0.1.18 — 只在拍照结束后自动打开 Wi-Fi

## 本次真机依据（2026-11-14 22:57–22:58）
v0.1.17 已经确认手机可收到合法 AA14 0x45 `isTakePhoto` 状态 `0→1`、`1→0`。但 v0.1.17 的2.2秒倒计时在 **22:58:24** 抢先发了一次 `0x39/0x30` 开AP指令，而同一秒之后才收到 `1→0` 结束事件。AA13写入status0后5秒仍无任何有效 `AA14 0x25` SSID，因而根本没进入Android Wi-Fi阶段。过早切模式可能是原因，但**尚未由真机证实**。

## 这次只删一个错误机制
- BLE待机不变，使用已证实的 AA14 `0x45` 状态事件；观察到 `0→1` **只等待、不启动任何开AP倒计时**。
- 只有收到 `1→0` 结束事件，才开始**250ms短暂收尾等待**，之后发**一次**既有原厂 `AB 55 00 03 39 30 69` 开AP指令。
- **彻底删除 v0.1.17 的2.2秒自动兜底**。如果这次没收到 `1→0`，BLE保持待机，无限期等待事件，不自动开Wi-Fi，也不反复发送命令。若用户确知已拍完，仍可点 **「我已经拍照，立即取高清原图」**；若已有传输，只反馈当前进度并拒绝重复提交。
- 「取消当前取图」/「停止并断开」按钮保留：停止等待时清理250ms任务、保留BLE；已发送AP时停止手机会话，防止迟到SSID触发下一轮连接。
- **不变部分**：AA13写成功后5秒`0x25` SSID超时明确报错；只对严检后的SSID尝试一次Android `WifiNetworkSpecifier`，无12秒扫描或1.8秒稳定等待；校验真实Wi-Fi Network/私有网关、原厂 `GET /app/getfilelist` HTTP200/result0，读取两次稳定的唯一最新候选并只读下载原始JPEG到手机RAM。最新文件不保证就是本次拍摄。无450ms连续轮询。

## 安全边界
不发送 `0x22` 遥控拍照、`0x44` 潜在删除指令、OTA；不上传云端/不保存相册/不删除眼镜文件。保留M02S及E09 MIT参考代码已验证的路径，不重新开发取图。 `0x45 1→0` 是上游状态字段，不代表固件保证JPEG已经完全写盘，是否能成功取到高清原图需要新的真机日志确认。

## 真机操作
1. 安装独立v0.1.18 APK，关闭其他眼镜控制App；点 **「准备蓝牙待机」**。
2. 按一次眼镜实体快门：关注 `0x45 0→1`、`1→0` 及 **1→0之后**的250ms AP发送。无结束事件时不会自动尝试；可以在确认已拍完后手动按取图按钮。
3. 看 `AA13 status0` 后5秒内是否返回 `AA14 0x25` SSID、Android `onAvailable`、私有网关/HTTP/JPEG尺寸和耗时。若还无SSID，立即复制匿名日志；**不要重复已成功的高清GET或旧12秒Wi-Fi扫描实验**。
