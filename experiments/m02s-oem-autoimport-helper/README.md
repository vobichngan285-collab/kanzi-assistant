# M02S 原厂相册「发现1个文件→导入」自动点击：独立无障碍试验 v0.1.0

## 目标与限制

用户原厂 `com.starglasses.app` APP v1.0.24-c / 固件 V1.6.1，原版连接 Wi-Fi 和高清原图下载相对稳定。目标不是重新实现其 BLE/AP，而是自动触发已存在的原厂 `导入` 按钮，让每次眼镜拍照后在原厂相册界面自动下载高清 JPEG 到手机。**「导入」指眼镜本地→手机，不是上传云端。**

已检查用户在当前会话提供的原厂APK（284656626字节）7个DEX，确认有 `com/starglasses/app/ui/activity/album/AlbumFragment`、`Ldp;.getUnImportNumLiveData`、`Ldp;.connectP2pWifitoReceivePhoto`、`Ldp;.startDownLoadPhotoByWifi`、`Ldp;.isImportNotFinished` 及官方APK资源UI字符串 `发现%1$s个文件` / `导入` / `导入中... (%1$s)`。这些证明原厂存在入库/连接/下载/计数业务逻辑，但**不能仅凭方法名断定哪个事件应自动调用哪个方法**。原厂拍照通知不是高清文件已写盘证据。

**当前提供的不是原厂二进制破解/重签包。** 原厂APK不是带可直接修改源码的Gradle工程，缺少经验证的安全重打包与签名链；直接修改原厂可能破坏成熟的Wi-Fi状态机、应用签名和账户配置。因此本轮先在**独立辅助APK**中做一个可关闭、可观察的无障碍UI自动点击验证。绝不声称原厂APK已被改动或已经完成自动入库。

## 逻辑

1. 辅助App独立包名 `com.vobichngan.bluestar.oemautoimport`，**不替换/重签/覆盖**原厂或正式蓝星向导。Manifest没有 `INTERNET`、`BLUETOOTH`、`ACCESS_WIFI_STATE`、`CAMERA`、文件访问、悬浮窗或无障碍以外的权限。无障碍属于敏感权限，用户需要明确在系统设置开启，也可以随时关闭。
2. 无障碍服务在 XML 和 Java 中都**只处理 `com.starglasses.app` 的前台可见界面**。检查节点中的原厂字符串 `发现1个文件` 与**完全匹配**且可点击的 `导入` 按钮；必须用户已开启本程序内的额外开关、先观察到原厂相册无待导入的状态、随后新出现一个待导入候选，且界面稳定约950ms。只调用一次 `ACTION_CLICK`，不尝试点击任何清除/删除/确认按钮、不滚动、不自动转屏、不后台截图。
3. 如果屏幕是其他App、候选大于1、旧候选没清掉、无按钮、导入中或系统无障碍拒绝动作，安全停止**而非自动循环点**。辅助工具**无法保证原厂App本身在下载成功后是否向眼镜发清除已导入媒体指令**；是否删除眼镜文件属于原厂既有业务行为，首次使用前需明确知悉。没有任何远程上传。
4. 只适用于**原厂App前台且相册界面可访问的场景**；熄屏、后台、系统对无障碍限制、页面换版与原厂 UI 按钮无可访问性时不保证工作。原厂 App 拥有所有 BLE、Wi-Fi、文件导入和下载逻辑，本实验不会替它发命令。
5. 本实验不是眼镜按键直接无屏朗读，仍需要后续验证提取导入后的高清原图并送 OCR，不能把自动点击导入等同完整功能。

## 单次实际操作

- 原厂程序保持原样，不卸载、不清数据、不覆盖；旧的待导入文件请先用原厂**手动**处理完。
- 安装辅助App，打开开关，在 Android 设置的无障碍服务里手动启用「蓝星·仅原厂相册导入」。
- 打开原厂App，**进入相册，先展示“没有待导入文件”的界面**；再用眼镜拍一张照片，保持原厂相册在屏幕前台。
- 相册出现 `发现1个文件` 且 `导入` 按钮时，辅助App尝试点一次。检查原厂有没有实际显示「导入中」、是否真正得到手机中的高清原图。
- 若不成功，返回辅助App点「查看匿名状态」，只提供对应状态，不提供图片、SSID、密码或文件名。
- 如需停止，关闭辅助App内开关或系统无障碍服务。不会修改原厂设置。

技术验证依据：原厂安装包实际DEX类/字符串；Android公开无障碍 `AccessibilityNodeInfo.ACTION_CLICK` API。UI触发成功率尚待真机验证。
