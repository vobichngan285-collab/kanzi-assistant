# M02S v0.1.8｜先蓝牙拍照，再连接 AP 取原图（独立实验）

## 已实测基础，不再重复
- v0.1.3：vivo X200 Pro / Android 16 + M02S-3584 蓝牙 AA13 0x22/0x30 真正拍照成功，有快门声；AA14 收到 0x22/0x42。
- v0.1.6：精准目标 AP + /app/getfilelist 成功解析 5 张照片，下载并内存显示 JPEG 原图 3200×2400、481424 字节、532ms。
- v0.1.7：用户真机反馈先连 AP 时拍照无声、45秒内未出现新照片。暂不能确定具体根因。

## v0.1.8 新顺序
1. 连接 M02S 蓝牙 LE1M，开启 AA14 通知，确认订阅 status=0。**不要提前连接 AP。** 如果眼镜依旧处于之前的 AP 传输模式，须先由用户使其恢复普通拍照状态，不能假设手机断网等于眼镜退出。
2. 点击「蓝牙拍照 → AP取图」一次。只发一次已验证官方 AA13 0x22/0x30；观察真实快门声。优先记录 AA14 的 0x22/0x42，哪怕累计通知超过原 40 条日志限制。BLE 写入成功或收到通知都不能单独证明拍照完成。
3. AA13 status=0 后遵守至少 5 秒指令间隔，再发送一次 0x39/0x30，请求 AP 信息。从 0x25 取得目标 SSID，再通过 Android 精准连接眼镜 AP。仅使用实际系统确认的独立 Network + 私有网关，绝不猜测 IP。
4. AP 连通才读取 /app/getfilelist。最多45秒，以约1.2秒间隔核对；候选图片连续两次文件名/字节长度/创建时间不变后才下载原图。复用旧 256KB 列表 / 32MB 原图限制，路径、签名、大小和分辨率校验。
5. **首次无拍照前列表基线，只下载唯一最新候选供人工核对，不宣称必然是刚拍的。** 若多个文件无法判断唯一最新，拒绝猜测；首次完成后仅在进程内保存 AP 列表供下一次拍照后比较新文件名。即便不同于前一份列表，也不等于严格因果证明。
6. 完成后解除**手机对眼镜AP的专属Network请求**，但不向眼镜发退出AP的未知命令，也不能保证眼镜本身退出AP传输状态。需通过下一次真实拍照判断。
7. 任务可取消；写入无回执、AP失败、新图片不稳定、HTTP/解码失败都停止，不自动重复拍照、不存相册、不上传、不删眼镜照片、不冒充旧图为新图。

## 真机验收
- 关闭原厂 HeyCyan，先让眼镜处于普通可拍照状态；连 BLE、订阅 AA14，**不要手动提前连 AP**。
- 对准与之前不同的新场景，点击一次「蓝牙拍照 → AP取图」并保持实验 APP 前台。观察快门声和 AA14 0x22/0x42，再检查 AP 网关、两次列表稳定、预览图是否是新场景。
- 首次取图后试下一次拍照，确认手机释放 AP 请求是否足以让眼镜恢复。若第二次无声，优先检查原厂 AP 退出模式；不要快速重复尝试。
- 失败只发送脱敏日志，不提供照片、SSID、文件名或口令。切换到 ChatGPT 后 Android 可能暂停或延迟定时轮询。
