# 蓝星 M02S 蓝牙协议观察 v0.1.2（独立测试 APK）

## 真机背景
用户的 vivo X200 Pro / Android 16 已在 v0.1.1 验证 M02S-3584 显式 LE + 1M 连接成功（112ms，status 0/newState 2），GATT 服务：1800、**AE00**（2特征）、**AA12**（3特征）、180F。此前 v0.1.0 默认 `connectGatt` 方式约60秒后失败；因此保留已验证的 LE 1M 路径。

## 新功能
- **查看特征 UUID/权限**：枚举 AE00、AA12 特征 UUID、属性（读、写、通知/指示）、描述符 UUID、是否提供标准 CCCD，**仅查看元数据**。
- **监听拍照通知（60秒）**：用户明确点击后，对 AE00、AA12 中带 Notify/Indicate 属性和 CCCD(0x2902) 的特征，顺序写入标准 CCCD 订阅值；只有这个标准 GATT 配置写入是必要的，不向任何厂商控制特征写入字节，也不发送设备拍照或开启 Wi-Fi 的私有指令。写描述符一次只执行一个请求，等待回调；5秒无回调暂停剩余订阅，避免并发蓝牙操作。
- **观察实体拍照键**：订阅完成之后，用户按眼镜上的实体拍照键。记录 60 秒内出现的通知 UUID、接收时刻、长度与最多20字节16进制预览；最多显示前40条，防止刷屏。内容可能包含私有设备数据，复制日志前请自行检查/遮盖。
- **停止通知记录**：停止记录和计时，不发送厂商指令；如需真正撤销订阅可主动断开 GATT。退出自动释放 GATT。
- 保留旧实验的蓝牙连接诊断、可选 Wi-Fi 检测，但尚未验证眼镜 Wi-Fi 会话，这次**不要求测试下面的 Wi-Fi 功能**。
- 独立包名 `com.vobichngan.bluestar.m02sprotolab`、版本0.1.2，不覆盖 v0.1.0/v0.1.1、蓝星向导正式版或眼镜官方 App。

## 官方 APK 静态交叉验证
上传的 `70465ff3819258a6218e7871da0a23f8.apk` 中，`classes2.dex` 检出 `0000aa12-0000-1000-8000-00805F9B34FB`、`0000aa13...`、`UUID_CMD_NOTIFY`、`UUID_PHOTO_NOTIFY` 等字符串；`classes4.dex` 检出 `0000ae00...`、`0000ae01...`、`0000ae02...` 和标准 descriptor 写入/通知方法。这些 UUID 与真机发现的两个服务对应，但**没有证明每个特征功能或发送 Wi-Fi/拍照的准确载荷**。现阶段不做冒险写命令。

## 手机测试
1. 关闭官方 HeyCyan 后台，打开测试 APK，并确认 M02S 开机、手机蓝牙与附近设备权限。
2. 点击“扫描眼镜 BLE（10秒）”，选择 M02S-3584，点“连接 LE 1M（15秒）”。应出现 status=0、新状态2、4个服务的日志。
3. 点击“查看特征 UUID/权限”，确认 AE00/AA12 的实际特征和 CCCD。
4. 点击“监听拍照通知（60秒）”。**先等界面出现订阅回调 status=0**，再按一下眼镜实体拍照键。避免连按拍照键，以便区分单次事件。
5. 点击“停止通知记录”或等待60秒结束，然后点击“复制诊断”，只发送特征清单、CCCD回调、通知日志（请先检查是否含有敏感数据）。
6. 若无通知，也属于有效结果：可能设备只在其他通道报告拍照或需要先发送厂商命令才能订阅；不能凭空判定眼镜没有蓝牙状态通知。
