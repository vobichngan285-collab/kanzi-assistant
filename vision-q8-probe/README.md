# MiniCPM-V 4.7 1B vision Q8 experiment
User v0.1.2 logs show CPU6 median/mean ~3.42s TTFT, vision ~2.71s; CPU8 no meaningful gain and Vulkan slower. All runs have 2 generation calls and no CER; this is not an OCR acceptance. New branch only. Use exactly the same pinned LLM and F16 projector; quantize only allowlisted 2D attention/FFN matrices of vision transformer blocks to GGML Q8_0. Preserve mergers, embeddings, projection, norm/bias, image configuration and tensor shapes. Verify source files by pinned HF revision LFS SHA256, verify quantized GGUF readback and nonquantized tensors/metadata. Host CPU CLI smoke on two synthetic 448x448 text images with distinct digits; logs report actual encoded time and answer; no user data, no phone speed claims, no release or model weight artifacts. A successful build/exit does not prove OCR quality. If baseline and Q8 output valid text, next Android A/B CPU6 with same pictures and reference text; retain F16 and original app. No change to formal Blue Star or v0.1.2/v0.1.3. 
NPU parallel research: Google LiteRT CompiledModel explicitly supports MediaTek MT6991 (https://developers.google.cn/edge/litert/next/mediatek). This is not GGUF runtime support. Community bundle https://huggingface.co/litert-community/MiniCPM-V-4.7-1B uses int8 vision variant; author reports CPU tests on Mali Pixel, GPU issues and Qualcomm NPU decoder rejection; no MT6991 MiniCPM result. Do not assume Qualcomm failure applies to MediaTek, or int8 GGUF equals NPU graph. Need extract/convert only vision, verify graph operators and runtime availability, compare embeddings and actual hardware execution before NPU integration. No NPU experiment yet.
