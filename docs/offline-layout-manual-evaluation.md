# Kanzi Assistant 离线版面 AI：手机实测流程

适用版本：feature/strict-offline-ocr-order-guard 实验 APK（PR #2）。
**注意：候选阅读顺序只用于诊断界面主动试听，不会自动替换正式播报。**

## A. 检查原文与阅读顺序

1. 安装实验 APK，打开设置，启用「实验功能：AI 版面理解 + 连续文字流规则」，保持 PP-OCRv6 Small。
2. 将摄像头稳定对准一本左右两页均有正文的书。打开「OCR 诊断」并运行。
3. 诊断结束后分别点击「朗读这次诊断识别出的文字」和「试听实验候选阅读顺序」。
4. 核对候选顺序是否完整读完左页才读右页、标题是否先于正文、段落是否被错插。
5. 点击「复制完整 OCR + AI 版面诊断」，将日志保存。日志包含每条候选文字的原始 OCR 框编号和版面区域编号。
6. 在牛奶盒上重复一次，重点核对品牌、净含量、营养成分与数字单位。**不要因为候选文本读起来通顺就假定识别正确**，必须对照实物原字。

## B. 隔帧缓存与功耗

1. 保持「AI 版面理解」开启，切换为快速扫读，摄像头对准固定文字，尽量保持稳定。
2. 等待多次自动 OCR 触发后，再运行一次诊断，查看「版面缓存统计」：
   - AI 实际运行：正常 OCR 中新执行版面模型的累计次数；
   - 缓存复用：相似且坐标保持一致的画面直接重用历史区域的累计次数；
   - 安全回退：画面变化过大、等待重新分析或缓存不可用时使用几何规则的累计次数。
3. 将镜头明显移向不同文字或翻转牛奶盒，再观察缓存是否被使失效并重新分析。
4. 对比 AI 开启与关闭时的 OCR 响应、发热、耗电。长文朗读模式会主动暂停重复 OCR，因此不适合用来评估缓存命中次数。

注意：**诊断按钮会强制执行一次新版面推理，并重置缓存**，所以诊断画面中的「AI 推理耗时」衡量的是新推理，不是缓存耗时。缓存统计只累计正常识别过程；诊断本身不计入。

## C. 出现异常时

- 「候选排序不可用」：某些非空 OCR 文字框没有合法坐标，新模块拒绝输出貌似完整的结果；请把原始逐框日志提供出来。
- AI 只检测到 1 个版面区域：仍可依赖几何分栏，不表示双页一定分对。
- 畸变、反光、运动模糊造成文字识别错误：排序模型没有权力修正、补充或臆造文字。
- 候选顺序差于正式排序：保持正式语音不变，记录样例用于修复后再考虑启用。
- 复制诊断之前请检查是否含个人、医疗、地址或其他私密文字，必要时删除敏感内容。

## 当前验收边界

- JVM 测试包括 OCR 框 ID 完整性、几何与 AI 混合的双页场景、跨页标题、倾斜文字行、牛奶盒样例、帧调度与亮度指纹。
- GitHub Actions Android 构建成功仅代表工程编译及签名检查通过，**不代表已在用户手机上验证准确率、延迟或发热**。
- 候选排序只有在多组真实图像上的版面顺序可靠、文字无遗漏、性能可接受后，才可考虑正式启用。
