# 看字助手 #315：低置信度新增文字框的价值研究（2026-11-03）

研究分支：`test/ocr-box-value-20261103`。本研究**没有修改发布分支、实际摄像头热路径或生成 APK**。

## 一、为什么需要推翻旧阈值基线

重新从 `release/v0.8.0-ocr-engine-rework/app/src/main/java/com/vobichngan/kanzi/PaddleOcrEngine.kt` 逐行确认后：

- PP-OCRv6 Small：`detThresh=0.20`（像素热力图阈值），**`detBoxThresh=0.45`**（文字框分数阈值），`detUnclipRatio=1.40`，最长边限制 1600 像素。
- PP-OCRv5 Mobile：`detThresh=0.30`、`detBoxThresh=0.60`、`detUnclipRatio=1.50`、最长边 960。
- 早前的 216 张图片检测 A/B 使用过 `detThresh=0.30`、`detUnclipRatio=1.50`、最长边 2048，且误把 `0.60` 解释为 #315 的 PP-OCRv6 默认检测框阈值；该数字只能作参数敏感性预实验，**不能作为 #315 基线**。
- 原有一部分识别 A/B 参考脚本也曾将颜色通道送成 BGR，而 Android SDK `RecPreprocessor` 在接收 BGR 裁剪图后会转换成 **RGB**。新实验已改为识别模型的 RGB 输入。原数据的 CER 不应被当作 SDK 逐像素复刻结果。

原检测和识别 ONNX、文字字典按原 APK 资产 SHA-256 校验。

## 四、为什么纯识别置信度过滤不够

另一个分析以预先选好的“两个及以上字符、识别模型置信度至少 0.75”为**输出过滤**：

| 低框阈值 | 额外识别总候选 | 过滤后可能朗读 | GT 匹配 | GT 全字正确 | GT 不正确/不完整 | GT 未匹配（未知） |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 0.40 | 39 | 13 | 8 | 3 | 5 | 5 |
| 0.35 | 92 | 24 | 14 | 7 | 7 | 10 |
| 0.30 | 137 | 30 | 15 | 8 | 7 | 15 |

这不构成可交付效果：GT 与模型可有不同分割；某些高置信度的新文字框也会漏首/尾字符，例如：

- GT=`MONTEREY`，OCR=`ONTEREY`，识别置信度约 0.9988；
- GT=`电话：13953177`，OCR=`电话：1395317`，识别置信度约 0.9988；
- GT=`TOUR`，OCR=`TOU`，识别置信度约 0.9958。

这些是检测/裁剪和实际字符正确率不是一回事的明显证据；对应画面与标注仍需人工复核，不能断言错误只来自裁剪。

## 五、非常重要：过滤的时间成本不能算错

Android 原 SDK 的 `OCREngine` 顺序是：检测框 → 阅读顺序 → **逐框执行识别模型** → 输出识别结果。

所以如果只是把 `detBoxThresh` 从 0.45 改成 0.35，然后再按“识别置信度>=0.75”过滤，**额外 92 个框的识别推理已经发生了**。即使只朗读其中 24 个，**仍不能节省另外 68 个框的模型时间**。

同一批 216 张照片的额外识别模型时间（仅云端 CPU ONNX 推理，不含预处理、Android/USB/TTS）：

| 检测框阈值 | 额外识别框数 | 额外每张照片 P95 推理时间 | 单张最差 |
| --- | ---: | ---: | ---: |
| 0.40 | 39 | 7.61 ms | 27.53 ms |
| 0.35 | 92 | 11.00 ms | 52.32 ms |
| 0.30 | 137 | 13.07 ms | 52.32 ms |

不能把 GitHub 服务器上这一计算耗时视为用户手机 USB 摄像头的真实性能。摄像头卡顿及语音响应需要真机验证。

## 六、下一步研究路线

1. 已从真实照片记录低分框的 OCR 输出：不是所有候选都值得朗读，更不是所有未标注框都应该删除。
2. 继续验证「从原图重新裁剪」对低分框截字是否比直接改变阈值更有效。**必须同时检查改善和退步**，不能根据 OCR 置信度自行挑选最佳答案。
3. 若后续设计“低阈值候选补救”，必须将过滤逻辑放在额外文字框进入识别模型之前，或修改 SDK 来实现单次检测后可控选框；不得额外每帧重跑完整检测模型。
4. 实时模式建议严格限制新增识别工作数量与时限，任何拟入软件的方案均需 USB 摄像头帧率、OCR 总耗时、真实朗读正确率及误播报率对照。
5. 目前保持 #315 发布分支原样，不建议更改真实默认阈值 0.45，不建议直接新建 APK。
