# 看字助手｜最终错误归因验证（2026-11-03）

**结论：暂停在现有 Small DET 上继续微调裁剪、局部放大、降低阈值和 PP-DocLayout-S 区域辅助。本轮没有测试任何新优化策略，也没有发现能够上线的准确率提升。此前“独立集只有50%行匹配”不能解释为“一半文字都未被检测”。**

## 复核范围与方法

- 实际完成：GitHub Actions https://github.com/vobichngan285-collab/kanzi-assistant/actions/runs/41566050026
- 分支：`test/ocr-final-error-attribution-20261103`
- 与前轮相同 72 张公开场景文字图（DEV 36 + HOLDOUT 36），无用户私有照片；461 行有效人工标注（217 + 244）。
- 完全使用先前的 SHA-pinned PP-OCRv6 Small DET + Small REC，框筛选原阈值 0.45；没有 Medium、视觉模型、第二次检测、裁剪参数探索、手机或 APK。
- 使用已有的 GT 人工多边形 AABB 与检测 AABB，对标准 IoU>=0.40 的一对一几何匹配失败逐行归因。另计算检测 AABB 与标注 AABB 的**任意相交**、标注面积被预测框并集覆盖的比例、标注中心是否在预测框内，以及 IoU 阈值敏感性。
- 再在成功几何匹配的文字区域上运行原 Small REC，报告字符错误率。仅从匹配行统计 REC，避免漏检 GT 对 CER 的混淆。
- **所有类别均是几何代理诊断，不等于人工目测证实的实际可朗读与否。**

### HOLDOUT 的 122 行“未匹配”分组（总和 122）

| 几何诊断类别 | 行数 | 占未匹配比例 |
| --- | ---: | ---: |
| 标注区域大部已被覆盖，但 IoU 未达 0.4 | **67** | 54.9% |
| 有部分重叠（偏框、弱覆盖等） | 9 | 7.4% |
| 有多个碎片框重叠 | 4 | 3.3% |
| 没有任何预测框与 GT 框重叠 | **42** | 34.4% |

其中“覆盖很多、IoU 不达标”不能自动视为“识别成功”：大框可能合并多个文字行，阅读顺序或裁剪仍会出错；同样“零几何重叠”也不能排除个别人工标注偏移，必须避免将几何分类当作逐行目测真值。

### 评价阈值敏感性

| IoU 阈值 | DEV 匹配行 | HOLDOUT 匹配行 |
| --- | ---: | ---: |
| >=0.20 | 157 | 137 |
| >=0.30 | 153 | 132 |
| >=0.40（预设） | 142 | 122 |
| >=0.50 | 135 | 112 |

仅调整**评价**匹配阈值而不重新运行模型，独立集匹配行从 122 变为 137。这不是 OCR 真实提升，只说明评价口径会显著影响所谓“漏检率”。

### 与前轮人工正确框 Oracle 的关系

相同 HOLDOUT 36 张照片、244 行，Small REC 在人工 GT 框裁剪图上的字符错误率 **9.734%**，运行记录 https://github.com/vobichngan285-collab/kanzi-assistant/actions/runs/41564703130 。

此项 Oracle 与自动 DET 匹配行 Small REC 的 16.087% CER **样本分母不同**，不能相减推定因果增益。它们共同提示文字定位、裁剪以及不同复杂度文字样本的影响应分开研究。

## 技术判断

1. “一半行未匹配 = 一半行完全漏检”是错误推断。独立集在原来 122 行未匹配中，有 **80 行（65.6%）与现有检测框有交集**，其中 67 行属于大范围覆盖但 IoU 不足；真正完全没有 AABB 重叠的有 42 行，占全体 244 行的 17.2%。
2. Small REC 不是完全无错误：在成功几何匹配的独立集 122 行中，33 行有识别错误、行内字符错误率 16.087%；因此也不能简单认定“只要框准 OCR 就一定读得正确”。
3. **当前 PP-DocLayout-S 不是适合替代精确文本行 DET 的模型。** 先前 72 图视觉辅助局部 Small DET 实验仅增加4个未重复框、0个成功匹配 GT 行，独立集平均推理时间从264ms增加到353ms： https://github.com/vobichngan285-collab/kanzi-assistant/actions/runs/41564405901 。
4. 目前证据不支持将布局模型上生产，也不支持继续无目标地微调现有 Small DET 的缩放、裁剪和阈值。之前 Small+Medium 识别复核仅在**已检测的字框**上有有限收益，不能补回真正没有框的内容。
5. 若今后确有新方向，应先定义严格**真实逐页朗读准确率和漏读**评价（包括框融合、重复播报、阅读顺序、数字内容），并采用未参与调参的新照片。现有本轮是最后一次归因验证，不再自动启动下一轮调参/改模型实验。

## 重要限制

- 同 72 张真实公开照片，与此前的模型试验有重叠，并不是新的前瞻性盲测集；HOLDOUT 仅指原先划分且未用于当时参数选取的一组，后续实验已用它复核。
- AABB IoU 与覆盖指标容易受大框、小框、多行融合和人工 polygon 标注偏差影响。相关几何类别反映现象，不构成精确的人工审阅原因标签。
- OCR 识别通道设置与前轮视觉 A/B 的 BGR 选择一致，但不是 Android SDK 真机端到端色彩/裁剪等价证明。
- 覆盖感知 CER 为代理：未匹配 GT 当作字符删除，但未把未配对所有 OCR 文字计入插入错误。不能拿它当真实整页 CER。
- 没有修改正式版 SDK、摄像头、翻页、朗读队列；没有构建/生成 APK。

**最终建议：本阶段停止优化和部署尝试，维持稳定 Small 基线；把现有 Small+Medium 的有限收益视为单独备选，等有更可信的实际朗读评估再决定是否集成。**
