# 蓝星向导 v0.5.0 云端视觉早开口优化实验（2026-11-06）

## 真机结果（用户截图，v0.4.0）
- 用户在 vivo X200 Pro 的手机后置摄像头下，云端视觉 qwen3-vl-plus，自动分辨率720p、上传82KB JPEG，**本机编码40ms、首句就绪1370ms、网络完整响应1530ms、端到端总计1582ms、输出50 Token**。结果是对墙上“刮痧”宣传单的简要描述。
- v0.3.0 旧版另一张“寒湿等级表”长篇回答耗时12677ms。该两次拍摄任务/图片/输出字数均不相同，只可说明用户感受到新版响应显著更快，不能当作严格同图速度提升8倍的基准。
- 当前相机与 OCR (qwen-vl-ocr) 在用户实际环境成功；OCR 之前一次识别1161ms，用户主观称准确率接近100%，不代表统计测量。

## 本轮代码修改（实验分支，提交 c3970b3de87a969eff8c34890b7db1f3073af11a，后续测试修复298403d333c00e3f21ac4a078d59124abbad3795）
1. **画质决策纠错**：原来的auto按「细节边缘少或黑暗」就升1080p，可能把黑墙/光线差错误升级；新版同时检测NV21明度Y平面1像素和4像素的梯度、亮度及方差，只有有可辨的柔和边缘时才考虑保留原生1080p，其余默认720p。该方法仍是保守经验性规则，不能准确检测虚焦、不能增加原图不存在的细节，必须真机A/B验证；设置中保留手动固定720p/1080p。
2. **视觉分句早朗读**：SSE流式回复接入独立 SpeechChunker；看到完整句号/问号/叹号时朗读，也允许逗号前已有至少14个字符时提前朗读有意义的分句；不强行切断无标点中文词语，继续遵循TextToSpeech.QUEUE_FLUSH首次、QUEUE_ADD后续排队，防止重复。
3. **TTS实际回调监控**：Android UtteranceProgressListener 记录该次请求第一个流式语音片段的 onStart 引擎启动（相对用户点击抓拍）和如引擎支持 onAudioAvailable 首次合成音频数据回调，异步更新诊断弹窗；**这两个回调都不等同于扬声器真正可听时间，用户仍需主观确认实际出声**。不记录原文/密钥/图片。
4. **OCR不改**：维持qwen-vl-ocr原提示词、同一调用方式和完整回复后朗读，保护已有识别质量；手机前后摄像头和原生USB UVC预览/采集文件原样沿用；遗留任务列表继续保持不变（用户要求正式版再精简）。
5. **Plus/Flash对照**：保留v0.4.0已有的 qwen3-vl-plus / qwen3-vl-flash手动切换，默认Plus，不自动切换不明免费额度的Flash；用户自行确认Flash额度与“用完即停”，避免误扣费。完全不在GitHub保存API Key。
6. **测试**：新增不依赖Android运行时的Java单元测试，验证中文分句边界/不重读/不漏字，固定分辨率与黑墙、软边缘、清晰画面策略。CI还编译含手机+USB摄像头的arm64 Android APK，静态检查不含本地OCR与秘密。
7. **下一轮实测说明**：同一张中文招牌/菜单在Plus模式连续3次测 v0.4/v0.5的首句就绪、TTS引擎启动与音频回调、总时长，尤其留意提前朗读是否断句；如Flash有免费额度，可手动切换与Plus做同场景A/B；画质选自动/固定720p/固定1080p，记录识别漏字和文件KB。不要凭本轮代码或CI声称v0.5已实测更快。
