# 看字助手｜独立单帧 OCR 图像证据诊断 APK（2026-11-03）

**这是实验安装包，不是正式看字助手更新版。** 单独包名 `com.vobich.kanzi.framelab`，与正式 `com.vobich.kanzi` 可同时安装。

## 用法

1. 在手机安装独立调试 APK，连接原来的 USB UVC 摄像头，或者选择手机摄像头，并给相机权限。启动后等 PP-OCRv6 Small 模型初始化。
2. 打开**设置 → OCR 诊断**（设置页面向下滚动到“OCR 诊断”）。
3. 对准一张字清晰、你知道正确内容的照片/书页/包装纸。点击**「手动采集一帧：图像＋真实裁剪＋输入张量（仅本机）」**。可在诊断报告中检查“单帧图像证据”保存状态。采集必须由你主动按键；正常实时朗读**不会**采集或上传。
4. 点击**「导出上次单帧诊断 ZIP（手动选择位置）」**，在系统弹出的文件保存界面，选择手机文件夹和保存位置。导出时系统保存一份文件，不会自动网络上传。请选择**非隐私**的测试画面，并在发给研究人员前检查内容。
5. 想对比不同图像效果，可以先在设置中切换**增强图像处理**开/关，然后分别手动采集并分别导出（每次新采集只保留最新本机 ZIP；先导出旧包再重采新包）。

## ZIP 包结构（公开给本人在电脑上比较）

- `frame.nv21`：手机摄像头给 OCR 的原始 NV21 单帧、无 JPEG 再压缩；从帧数据可重新重建输入。
- `decoded-frame.png`：从原 NV21 经 OpenCV 转成 RGBA/Bitmap 的图像。
- `actual-ocr-input.png`：这次诊断**真正送进 SDK 检测器**的 Bitmap（增强开启时可与 decoded-frame 不同）。
- `metadata.json`：帧尺寸、模型 ID、原框数量、实际导出数量、每个框四个坐标、原识别文字、置信度、裁剪宽高、送入 REC 的 NCHW tensor shape 与执行时间。
- `crops/000.png` 等：调用**同一份**官方 PaddleOCR v3.7.0 `QuadTextCrop.crop` 得出的文字裁剪图（最多前24个；无第二次 OCR）。
- `tensors/000.float32le` 等：调用**同一份构建时 BGR 补丁**的 `RecPreprocessor.preprocessBatch` 得到的 NCHW float32 LE 二进制数组，shape 记在 JSON 中，可做精确电脑端数值比较。

> 注意：crop/tensor 是对这次 OCR 返回的四点框在原 Bitmap 上再次调用 SDK 裁剪/预处理，仅用于记录，可对比正式识别链路算法；没有额外 DBNet/REC 推理。本工具不会凭空提供人工正确框，需要人眼核查是否切字、漏字或跨行。

## 数据保护与限制

- APK 已移除 Android `INTERNET` 权限，证据写入应用私有目录；**只在你手动导出时**通过 Android 系统文件选择器复制到你选的位置。不会自动上传 GitHub、云端或聊天。
- 默认覆盖上一次在应用内部存储的证据包，最多导出24个 SDK 返回框；源帧 PNG、NV21、OCR 文字很可能包含个人隐私。不要拍银行卡、身份证、医疗文件或其他不希望分享的信息。
- 删除实验 App 会删除私有存储的最新采集；**已主动导出的 ZIP 不会被自动删除**。
- 这是 Debug 签名实验 APK，不是经手机实际安装与摄像头运行验收的正式产品。保留原版，无需卸载。诊断版不支持联网下载原有可选语音资源；内置 OCR 模型可离线工作。

## 研究目标

先定位**源帧画质 / NV21 解码 / 增强 / DBNet 原框 / QuadTextCrop / REC 张量**是否存在实际手机端问题；对照此前固定公开真图的同122区域 CER（自动框16.087%，人工GT框5.797%），不要把公开云端实验误当成手机实测提升。实验 APK 的成功构建并不代表手机识别率提高，正式版模型/识别参数、白框/TTS 不因本次诊断自动改变。
