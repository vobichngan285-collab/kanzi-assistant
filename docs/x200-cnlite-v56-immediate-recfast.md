# v56 实时新字立即抢读 + ChineseOCR-Lite / Small REC 速度优化

此版本基于已验证正常划框和朗读的独立 v55 应用 `test/x200-cnlite-live-ocr-v55-20261105`（构建源码 `23a10e664eb8c290b80d1aa01c175208688b68b2`），在同一 `kanzi-assistant` 原仓库创建 v56 独立分支。原 v55 APK 不变、旧 Small DET 继续回退可选。**不增加新的文字合框、补字、语义重写规则。**

## 新的用户指定播报规则

- **默认“实时文字”自动模式：** 同场景重复或只有少量 OCR 差错，保持原语音；一旦任意**一次完整OCR**实际识出明显不同的新文字（区别采用原 `RealtimeSpeechGuard.sameTarget` 文字判定），**立刻中止正在读的 TTS 与旧队列，直接开始新内容**。不需第二次OCR确认，不等旧一段读完。无文字/无TTS引擎不会触发。
- 系统 TTS + 已安装本地自然音色 TTS 均沿用原停止接口。迟到的旧 TTS onDone 回调不会推动新队列（utteranceId 必须与当前句匹配）。
- 摄像头廉价亮度帧观察在朗读时继续，识别不再因 `speechPageActive` 被阻止；场景发生变化时允许下一次 OCR 工作。一次最多一个完整 OCR 在跑，仍有 `recognitionIntervalMs` 和 2帧亮度防抖，**真实切换下限取决于一轮DET+REC完成，不是检测框出来的234ms就可播报新全文**。
- **手动选择“长文阅读”** 仍然保持读完整页的原行为（保留给需完整听长文的人），设置中可以切回实时抢读。新模式下新页切换会中断当前文章，需要用户知情。
- 自然场景中自动曝光和转焦引发的文字差异仍可能误触发抢读；严格以真实摄像头音频/视频判断，不声称百分之百无重复。

## REC真正瓶颈与可回退的第一次实验优化

- 用户真实价目表30行/30框、CN-Lite DET 234ms、逐框Small REC 902ms：**原1批1行**，每框单独透视裁切、48像素高缩放、分配FloatArray、单独ONNX调用、把约18710类CTC浮点概率从native拷贝到Java并逐时间步argmax，直接造成次数累积。每框平均约30.1ms，但上述分段比例未由该价目表原始JSON提供，不应推断全部时间在ONNX。
- v56 fresh install 默认 `REC_FAST2`（2个CPU线程、每批2个框），使30个框由约30次REC ONNX推理调用减少为约15次。**这只是结构性优化，手机端实际更快与否必须实测。**
- 独立工作流对固定 PaddleOCR v3.7.0 安卓 SDK 进行小范围、可核验补丁：对 **Small REC** 批处理时用检测四点框的几何长宽比估算裁切后的宽度，尽量将**相似宽度的行**分在同一批，减少同批不同长度文本之间的零填充；仍逐框用官方 `QuadTextCrop.crop`，**最终按原阅读顺序索引恢复结果**。字典、REC模型权重、原始检测坐标和文本内容不变。
- 原 `BASELINE`（2线程/每批1框）仍在设置里可选，可直接通过相同手机/相同页的单帧诊断比较。批2可能在部分设备上反而增加延迟/发热；检测到问题立即回退批1，不能拿Linux runner成绩当vivo结论。
- “单帧诊断”及 Android Log 输出 **REC 预处理/ONNX推理/CTC解码/批次数/输入形状**，用证据判断哪一段在占据约900ms；同时核对CPU热状态和实际掉字情况。
- 模型字节完全不变，使用原 CN-Lite DET（RGB短边640）和原 PP-OCRv6 Small REC（BGR 48高、同字符表）。两个模型严格离线，未接任何生成式模型/云端接口。
- GitHub Actions 校验小批2 ONNX输入可运行、每一条输入与单批CTC argmax一致、安卓源码映射正确、旧相机/竖排/朗读稳定性静态测试、APK签名与无INTERNET权限；真正的连续朗读与热状态需vivo X200 Pro实测。

## 建议明天测试

在应用中切到“实时文字｜新文字立即打断”，开启自动识字。先拍一页正在朗读的课本，立刻切换另一页，应**在下一次完整OCR新字出现后**停止上一段，听到新页第一行。对同一页停留、改变光照、轻微晃动，不能无限重复读。使用诊断分别选批2和批1测三次同一张价目表，观察REC分段时间、读出的字、热状态；若批2的漏字或延迟恶化，直接选批1，不需卸载。
