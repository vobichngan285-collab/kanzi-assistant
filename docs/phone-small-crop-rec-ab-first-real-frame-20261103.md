# 看字助手｜真实手机价目表的 Small REC 原框 vs 横向裁剪局部 A/B（2026-11-03）

## 结论：这张图的4条目标行全部可以由**原版 Small**准确识别

本次在本地容器使用用户自愿上传、已在上一轮核查无严重解码/张量异常的**同一帧1080×1920手机拍摄图像**，以及与正式 Android 构建相同 SHA256 的官方 **PP-OCRv6 Small REC ONNX**。只针对已有的检测异常区域重裁剪并重新进行 **REC**，没有再跑 DBNet/CRAFT、没有换识别模型或词典、没有采用语义补字、没有重新编译手机 APK。

**数值结果：** 用户原手机保存的6个 REC Float32 张量重新推理，**6/6预测文本逐字与当时手机记录一致**（包括已有异常15/16/17及独立字片19/21/22）；然后对同图中4条横向文本行，按人工可见原图视觉转录的每行4个字来核对，**4/4完整行完全正确，16/16字符正确，16字符的局部编辑数0**。该人工视觉转录由研究者从照片读出，**尚未请用户逐字复核**；这不代表整页 CER 为0，也不能按旧纵向单框数量直接算同分母“下降了多少百分比”。

## 第一轮：人工确定的横向行框 + 同 Small 识别

- 原源图中该区域有四条可见的中文横排文字，**每行4个汉字**。研究者先从原图独立阅读这4行（非模型推断），作为本实验**未由用户确认**的临时人工文字真值。
- 按原图几何覆盖四条水平字行、排除右侧点线和价钱部分，生成4个横向单行裁剪并送入同一 pinned Small REC。
- **4/4整行精确匹配**，**16/16汉字精确匹配**，对上述手工转录的局部编辑数为0；前述原 SDK 的三个竖向跨行裁剪仍会生成错误的混合字串。
- 对每行另做两种裁剪高度扰动（较窄36像素，较宽50像素）：每种4/4整行正确；额外的逐字符分块方案每行4个独立字符候选，4/4整行也正确，但推理次数显著更多，因此**没有理由把逐字多次 REC 直接搬到手机**。
- **这些裁剪尺寸扰动来自同一张照片，不能把它们当作12张独立样本来统计准确率。**

## 第二轮：利用已存在的框坐标自动产生4个候选条带（仍是影子实验）

- 输入仅来自先前已经完成的`CrossRowOrientationAudit`只读风险输出的3个“疑似跨横行竖框”和伴随的3个横向、彼此对齐的价格行锚点。**不读取锚点上的中文词义**，只读取现成四点框、图像尺寸。
- 算法：从风险框的左右边界加常数比例字体高度的小外扩，得行文字的横向 `x` 范围；由价格框的高度中位数估算字体高度、各价格框的 `y` 中心建立3行；若相邻行距一致且最深处异常框底部确实延伸到下一行，才向下**外推最多1行**。共生成4个窄横向区域，避免再次进入完整 DBNet。
- **在这张真实图的已标记局部区域中，几何自动生成的4条横向框也达到4/4整行精确匹配、16/16字匹配，编辑数0**。这是**本地 Python + Linux Small REC**，未接入手机；本地工具仍带着这张图的实验断言，尚未建立可通用部署的产品实现。
- **绝对不能说这些候选自动“纠正了正式版”**：原手机软件仍使用旧纵向框，未修改原文和TTS；本次先证明了“如果正确分行，同一个Small能准确读字”，下一步才是可部署且安全的自动分行判定。

## 验收边界与为什么不能直接启用

1. **只有1张同一手机照片、4条目标行**。原图横排四行人工视觉转录不等同于用户标注的大样本 GT；不存在独立盲测，也没有测整页字错率。
2. 原来3个异常框与新4个行框代表不同分割单位，**不能把3个错误字符串直接与16字目标按同分母CER相减**；只可以报告老框确实跨行、新候选4/4字行与人工目视文本一致。
3. 过去的 **真竖排 + 旁边排列了水平价格锚点** 合成强反例，当前几何风险算法也会报警，因此若立刻自动重裁剪/覆盖原文，存在把真竖排毁掉的危险。**当前只读影子候选，绝不写入真实朗读文本**。
4. 新 Linux CPU 推理耗时不等于用户 Android UVC/Camera2 额外延迟、耗电或发热；没有做这些指标的手机实测，也没有新 APK。
5. 旧诊断包仅保留前24/36个最终框，可能遗漏同一画面下方其他元素；不要以本轮成功代替对全页漏检的检查。

## 后续建议与停/走门槛

- **技术结论**：本例瓶颈集中在跨行检测框/裁剪方向；保持Small+现有图像通道，下一研究应强化多行/竖排判别，而不是换大模型或对原文做语义推测。
- **停/走门槛**：收集**至少一张真竖排**（尤其邻近价格/横排元素）、同一表格不同角度，最好再有不同字体/间距排版；人工先区分真实纵排与横排。只有风险判别在明确反例中安全时，再在实验手机 APK 中启用“默认关闭、手动比对”的局部二次 REC 候选。
- 仍保持当前正式看字助手及原独立手机诊断 APK 不变，未修改现有用户播报内容或白框。

**阶段判断：在这张真机照片中，自动生成横向单行裁剪 + 原版 Small，可以从原来混读错行恢复为4条完整且准确的中文服务名；方案“存在可改善能力”已得到实证，但“能在所有场景安全自动改善”尚未证明。**
