# 蓝星向导 v0.4.0 自适应分辨率与视觉响应优化（2026-11-06）

## 用户实际反馈（v0.3.0）
- 手机后摄、阿里云北京地域普通 API Key、云端识别及本机朗读已真机跑通。
- 用户反馈 OCR 识别准确率近 100%，一次截图识别耗时 1161 ms，任务“原样朗读文字” → qwen-vl-ocr。
- 用户反馈视觉任务“逛商场”一次耗时 12677 ms，返回很长的寒湿等级表说明；使用 qwen3-vl-plus。
- 上述为**两张不同图片、不同任务的单次用户结果**，不能按此认定模型本身速度提高/降低，也不能认定 OCR 有经统计核实的 100% 准确率。
- 源码确认 v0.3.0 FrameCompressor 已按**长边 1280 像素**压缩，直观上就是横幅1280×720或竖幅720×1280；因此此前视觉 12.677s 不是简单的“上传1080p导致”，优先怀疑非流式等待和长文本生成。

## 本次功能实现（实验分支 exp/cloud-vision-usb-click-v1-20261106）
1. 保留原生 USB AUSBC + Camera2 手机前后摄像头、拍照一帧、Android TTS、本地加密 API Key、百炼北京端点；不加入本地 OCR。
2. 对拍照**原始 NV21 Y 明度采样**计算高频边缘比例，作为轻量“细节不足”风险线索：默认细节足够→长边1280（720p）；细节不足且原生最大边≥1600→长边1920（1080p），**绝不凭空放大小图**；无额外 AI / 不多拍 / 不重复收费。阈值0.014属于经验启发式，不是经过验证的失焦/文字质量分类器，复杂背景、低光、低纹理场景可能判断不准。提供设置：自动、固定720p、固定1080p以便真实 A/B。更大分辨率只是保留源图细节，不会让失焦照片变清晰。
3. OCR保留 v0.3.0 模型和任务指令，非流式单张请求，输出长度上限1200，不动已经验证的识别流程。
4. 视觉请求改 stream=true (OpenAI兼容 SSE)；首句出现标点后直接排队本机 TTS，完整回复完成才弹结果窗。普通视觉任务提示词限制简短、禁止Markdown、最多约三句；菜单和自定义保留较长内容预算（菜名价格/自定义任务不可截断为50字）。
5. 视觉默认使用原来的 qwen3-vl-plus；设置可手动选 qwen3-vl-flash做 A/B。**切换flash前用户必须确认其单独的免费额度并开启用完即停**；实验阶段不自动把模型改成未核实计费的模型。
6. 弹窗显示本机JPEG编码耗时、首句就绪、云端完整响应、端到端总耗时、上传大小、分辨率、模型与可用的output Token；日志只写数字与模型/任务路由信息，不写密钥/照片/识别原文。
7. 当前任务列表为 v0.2.0 遗留占位，用户明确本次不要处理；正式版必须恢复最终冻结的6任务+3×3 UI设计，删除“逛商场/场景识别”。此次独立实验版不代表正式界面已实现。
8. 当前直连阿里云 API Key 仅为自己手机封闭实验，存储经Android Keystore加密、不会上传到仓库。正式发行须使用安全服务端代理，不能将公用密钥写进APK。

## 性能实验步骤（用户手机实测，禁止伪造结果）
- 同一物体、同一手机镜头位置、同样光线做三轮，每轮分别设置“固定720p”“固定1080p”“自动”，先用OCR同一中文图片测试，再用视觉同一招牌/菜单测试。
- 每次抄录：模型、分辨率决策、JPEG KB、JPEG 编码 ms、首句就绪 ms、完整请求 ms、总耗时 ms、识别有无错漏。默认 plus 模型下完成分辨率 A/B，再确认 flash 免费额度后单独比模型。
- 观察第一声实际响起时间与“首句就绪时间”的差异：前者还包含主线程和 Android TTS 引擎排队；本测试版不自动测TTS首帧发声。
- 弱纹理导致的1080p不是无条件提升准确率，若连续表现比固定720慢又不准确，应调低1080触发率，优先实际测量。
- 由于无法访问用户自己的 API Key，GitHub CI能验证编译和安装包完整性，但**不能替代实机的OCR/VL正确率、实际云端耗时、计费和外接USB测试**。
