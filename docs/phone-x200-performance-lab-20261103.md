# 看字助手 · X200 Pro 离线 OCR 性能实验版（Android Debug）

**隔离包名：** `com.vobich.kanzi.x200lab`，与正式版 `com.vobich.kanzi`、旧单帧诊断包 `com.vobich.kanzi.framelab` **并存**。不使用正式签名，不改正式版。版本：`0.9.9-x200pro-performance-lab`（Android 8+）。

## 用途及界限

此安装包专为用户给出的 **vivo X200 Pro / 12GB RAM** 优化测试，但不预判哪个参数一定更快。PP-OCRv6 Small DET/REC 权重、PP-DocLayout-S 和既有OCR文字组织逻辑不变。单机全离线，**APK没有INTERNET权限**；诊断ZIP仅保存在本机私有目录，需用户点击“导出”并手动选择路径。ZIP可能含私人文字，请自查后分享。

* 对照：**2个ONNX CPU线程、REC batch 1、0个附加候选**。完全沿用原实时OCR单模型参数。
* 均衡：**3线程、batch 2、手动诊断最多2个额外候选**。
* 高质量：**4线程、batch 2、手动诊断最多4个额外候选**。
* 吞吐对照：**4线程、batch 4、最多4个额外候选**。这档是压力实验，不能预先说一定更快；如果ONNX不支持可用设置返回对照或继续使用对照档。

**重要：** 所有档位改变的是整个实验APP的ONNX线程/识别批量；但是“竖排异常追加REC”**只在用户点击手动OCR诊断时运行**，在正式实时扫描与TTS中**绝不自动替换任何字符**。额外REC只针对：原框极细长、上下角X区间不交叠、原始Small仅识别≤3个Unicode码点的真实竖排风险框。候选只有识别≥10码点且置信度≥0.8时才标记“建议”，但始终保留原文。额外候选来自同一帧真实像素和相同Small REC，不进行语义猜测，也不额外跑DBNet。Android热状态>=严重级别或OS内存压力时取消额外REC；热状态中度时最多2个。

## 手机测试步骤

1. 安装该debug APK，可与原正式版/旧诊断版同时存在。手机摄像头和USB相机都保留。
2. 打开“设置”→“X200 Pro / 12GB 离线OCR性能实验”，先选“对照：2线程/批1”，点保存；等OCR模型重新加载好。
3. 用手机支架让同一印刷文字/真竖排物体位置固定，点击“设置”→“OCR诊断”→“开始OCR诊断”记录DET、REC、总耗时、诊断墙钟、热状态、剩余RAM、Java/Native内存。建议一档连续拍3张，记每组中位数，再换另一档。要严格配对，可以用保留的原始诊断ZIP审查是否同一画面，但目前APK没有“一键同帧切换所有配置”。
4. 依次测“均衡3/批2”“高质量4/批2”“吞吐4/批4”；每次修改会重新加载模型。建议先等待设备恢复稳定再测，不要把第一帧冷加载混入稳态统计。
5. 用之前真正竖排介绍牌重点验证异常长列。高质量档的诊断文本会显示“原始识别 → 候选识别”、额外REC耗时与是否通过保守门槛；**候选不影响朗读**。普通横排、价格表则验证是否有错误触发，不能根据伪高置信度擅自修字。
6. 可以继续“手动采集一帧（图像＋真实裁剪＋张量）”→“导出诊断ZIP”，现在 metadata.json 另外写入 profile、threads、batch、shadow预算，以便一一对照。采集时诊断成本包含附加候选，所以与旧单帧总耗时对比务必区分原始DET/REC与附加部分。

## 性能判断

* 原手机两张困难样本的旧DET+REC合计约1.34–1.61秒；**这些是过去实测，不是新模式速度承诺**。
* 记录每一档同场景OCR耗时、内存和温度等级，再决定哪个档最适合X200 Pro。RAM 12GB不等于全部可供APP使用，也不保证4线程、batch4会胜过3线程、batch2。
* **本实验仅经GitHub CI编译/安全静态验证，不代表助手已实机安装或量到X200 Pro上的真实加速/发热。** 必须由用户实际手机测试。
* 旧用户两份手机诊断原图、私字与张量从未上传GitHub或公开CI。

## 失败处理

遇到编译通过但某档设备OCR初始化/识别失败，返回“对照”并重新初始化。若连对照档失败，保留原正式版继续使用，导出诊断文字，不需要重装正式版。本实验包已移除INTERNET权限，不支持需联网获取的语音资源下载。

**产物：** GitHub Actions独立 Debug APK，CI仅发布临时 Artifact，不创建正式Release，不修改正式分支的可执行源码。
