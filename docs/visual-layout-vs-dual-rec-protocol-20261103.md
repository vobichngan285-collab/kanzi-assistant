# 视觉辅助 vs 双识别模型：独立横向实验（设计冻结，未运行）

## 目标与隔离
验证用户假设：当前 OCR 的主要损失是否来自文字行定位、漏框、断行和阅读顺序，而不是识别器本身。先测试 **Small DET + 视觉布局辅助 + Small REC**，不接入 Medium；随后与现有 **Small DET + Small REC + 条件 Medium REC** 横向比较。正式版、相机、翻页、TTS、SDK 默认识别入口均不修改；禁止生成 APK。

## 固定三组
- A / baseline：原始 Small DET + Small REC；保留正式版 BGR 输入、检测参数和排序逻辑。
- B / layout-only：同一 Small DET 和 Small REC；增加 PP-DocLayout-S（仓库已有 ONNX 形状验证脚本），利用布局框确定栏/段顺序；在预先固定的可疑区域做 **Small DET 局部补检**，并用确定性规则合并去重；**不得调用 Medium REC**。
- C / dual-rec-only：与 A **完全相同的 Small DET 框**，按此前已声明的 Small 置信度 <0.95、每图最多 1/3 次 Medium REC 复核；**不得调用布局模型**。

B 组若只改变排序、不增加文字框，则只能声明阅读顺序收益，不能宣称漏检率改善。视觉模型输出的是区域/类别，不把它当成逐字识别真值。

## 数据和防泄漏
1. 采用相同真实公开照片及其人工标注 polygon/text；先固定开发集与独立保留集，避免按结果挑照片。
2. 在完整照片上运行 A/B/C，不得拿 GT polygon 代替 DET 框来报告整页指标。之前 BGR 72 张 GT crop 研究只能当识别器上限参考。
3. 每张图使用同一像素输入、方向和 BGR 预处理；记录原始 DET、布局框、补检框、去重结果、最终文本和顺序。
4. 视觉补检区域选择只能依赖模型输出和几何规则，不得根据 GT 或识别错误选择区域；开发集定参数，保留集一次性评分。
5. 使用同一批图像测量 CPU 推理延迟和峰值 RSS；模型首次加载与稳态分别统计。云端 Linux 数据不可冒充 Android 手机结果。

## 主指标
- 行级检测召回率、精确率、漏框率：预测框与 GT polygon 以预先固定 IoU/覆盖规则匹配，报告匹配规则；对断行、合并行、倾斜行分层。
- **整页 CER**：对全部 GT 文本评估，不能只在被检出的框上算 CER（否则漏框被忽略）。
- 阅读顺序：人工标注的区域/文字行顺序，报告顺序对错误率；双栏/表格与普通单栏分开。
- 每图端到端 P50/P95/P99，模型加载峰值/稳态 RSS，新增模型磁盘体积；对低光、模糊、小字分层。
- 数字、价格等关键内容单独统计漏检与误识别。

## 防止误判
- 先检查 A/B **相同匹配框**上的 Small REC 字符准确率是否相同；不同则需说明裁剪或预处理变化。
- B 若只是增加更多假阳性框，不能只报召回率；需同时报告 precision、误读/多读行数。
- C 必须用 BGR Android 对齐识别结果，不可直接拿旧 RGB Python 研究的 CER 与 B 组比较。
- 报告 paired per-image 差值、bootstrap 95% 区间，禁止仅凭个别示例宣称胜出。
- 如果 B 的整页准确率收益更大、且额外 P95/RSS 可接受，优先 B；如果 C 收益更大，优先 C；若二者都小，维持 A。**本阶段不做 B+C 叠加**。

## 运行状态
当前仅建立独立实验分支和冻结对照设计；**尚未在相同全图数据上运行 B/C 横向推理，因此没有任何新的准确率提升数字。** 下一步是实现布局推理、局部补检及全图评分工作流，再运行独立保留集。不得把已有双模型 CER 或 GT crop 数据冒充本实验结果。
