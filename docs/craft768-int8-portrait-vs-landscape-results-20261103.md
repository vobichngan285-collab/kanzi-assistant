# 看字助手｜CRAFT768 INT8 保持原始宽高比 vs 旧版强制横屏留白真实照片对照（2026-11-03）

## 结论

本轮**已完成**72张公开场景照片 A/B，证明纠正“竖图先放入横向1920×1080画布”的输入链路，是有实际文字检测价值的改动：

- **HOLDOUT 36张/244行**：旧白边链路 137/244 行匹配、覆盖CER代理46.339%；新直接保持照片比例链路 **145/244 行匹配、代理41.265%**，+8行、代理错误率减少5.074个百分点。
- **DEV 36张/217行**：旧链路115/217、新链路136/217，+21行；覆盖CER代理51.642%降到43.035%。
- **仅竖屏 HOLDOUT 8张/85行**：旧匹配36行、新匹配37行；未匹配GT字符181→133（少48），但匹配行编辑距离17→38（增加21），覆盖CER代理58.754%→50.742%。样本只有8张，因此不能承诺对所有竖屏真实照片有显著提升。
- **仅竖屏 DEV 15张/88行**：旧30行→新45行，代理62.579%→43.975%，提升明显，但仍然是反复使用的公开照片。
- 代价：Linux CPU的HOLDOUT平均完整检测+Small REC耗时**1038.14ms→1093.84ms**（增加约5.4%）；仅竖屏HOLDOUT平均**1041.79ms→1313.09ms**（增加约26.0%）。竖图不再在横屏白边中占较小面积，模型收到更多有效细节，同时真实计算成本也可能更高。**不得把这个主机耗时等同手机测试耗时。**

这轮只验证了**原版固定INT8权重 + Python/OpenCV既有文字框重建 + PP-OCRv6 Small REC**的几何匹配/覆盖CER代理。Android新版本使用纯Java几何后处理，已通过合成单框/双框/低置信度/链接测试，但并未通过真实图片逐框OpenCV对齐或全页字符朗读真机验收。

成功 Actions：https://github.com/vobichngan285-collab/kanzi-assistant/actions/runs/41588974116

## 唯一变量和实验完整性

- 研究分支：`test/craft768-int8-portrait-boxes-20261103`。
- 模型相同：CRAFT768 QDQ INT8 ONNX 20,946,608 bytes，SHA256 `9ab885d2f6669b77f70e9c8f68acfbe408c0b051501fd02d94bcaa0c7779ab15`，所有数据同一GitHub Linux CPU runner运行。
- 前处理：两条链路都使用同样CRAFT ImageNet RGB归一化、最大长边768、向上32对齐，阈值、OpenCV后处理和Small REC识别器保持一致。
- 旧：原照片保持比例先置入带白边的1920×1080画布，CRAFT检测后框坐标逆向映射回原图，统一从原图裁切给Small REC。
- 新：原图直接输入CRAFT，照片原始比例保留，检测框直接映射回源图裁切给同一Small REC。
- 旧图像框逆映射会有1~2像素插值/四舍五入差异，这是候选实际输入链路对照，不是等价算子数控实验。
- GT只用于评分，评价AABB IoU≥0.4匹配行；coverage-CER代理包括未匹配GT字符惩罚，但不包含全部预测插入字符；**不等于真实朗读的错漏字率**。
- ReCTS/RCTW/ART每个数据源DEV12、HOLDOUT12，共72张，先前已用于其它模型研究多轮；HOLDOUT并非全新未知样本。

## 真机测试与新版APK

新独立Android诊断测试应用已构建：同一原量化SHA的20.95MB模型、离线、无互联网权限，新的独立包名 `com.vobich.kanzi.craftprobe.portrait`，并有明确的“CRAFT竖屏文字框实验”启动标签，不覆盖旧实验App或正式看字助手。

成功新版 APK CI：https://github.com/vobichngan285-collab/kanzi-assistant/actions/runs/41589068935

- Android Java代码保留照片竖横比；如1536×2048原图直接获得大约576×768的输入，旧白边路径在用户手机JSON里是768×448，面积增长约29%，可能增加手机耗时，尚不能以LinuxCPU代替测试。
- 增加可选CRAFT检测框黄色轮廓预览、候选框数、后处理耗时。后处理算法用CPU纯Java实现，已在编译工作流中通过合成图测试，但不宣称与Python/OpenCV输出逐框完全一致。
- **用户现在只需要把旧版 ⑥ 连续24次测试重复6轮并导出旧版JSON**，不应强制用户做专业图片/框验证。
- 分析旧版6轮PSS增长后，再决定是否需要新版实际设备测试。新版无需用户现在额外操作。
- 新版不包含Small REC真正文字转录、不包含从OCR结果到TTS播报。

## 不代表什么

- 不代表正式版用户真实照片文字漏检率下降多少，或真实阅读CER；
- 不代表新Java版文字框与OpenCV精确一致；
- 不代表真实Android实际完整读字速度，也未测新增Small REC和TTS首字发声；
- 不能认为未配对框全部是假阳性；
- 没有修改/合并正式应用分支，未生成或替换正式看字助手安装包。
