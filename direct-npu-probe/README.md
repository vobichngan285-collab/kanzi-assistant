# Direct OCR / MediaTek NPU probes
Independent research only. No Android APK, no formal app edits. Previous Android JNI 4.7/471 already uses empty thinking scaffold; previous host CLI used generic template, so do not assume phone was thinking. Host A/B uses same explicit ChatML prefix and same F16 vision / Q4_K_M LLM and three synthetic text cards; compare prefill+generation (excludes cold model loading), output, tokens and whitespace-normalized CER. Opening/closing scaffolds differ deliberately. Android actual version dispatch and two-token results remain to be verified. Not claiming device speed or actual audible TTS. 
NPU separately uses community converted LiteRT-LM int8 vision bundle, pinned by SHA256, NOT GGUF. Official MediaTek AOT Python example target MT6991; extract only explicitly named vision encoder section with official unpack command, no text decoder or adapter. Official SDK nightly package versions may vary; save pip freeze. Compile report must be inspected for actual delegated partitions, output files alone are not proof. Android 16 device dispatch, adapter and GGUF embedding compatibility are not tested. If tooling unavailable or graph fails, retain error rather than assume NPU impossible. No model weights in artifacts. Sources: https://developers.google.com/edge/litert/next/mediatek ; https://developers.google.com/edge/litert/next/npu ; https://huggingface.co/litert-community/MiniCPM-V-4.7-1B ; https://openbmb.cn/docs/guides/minicpm-v/minicpm-v-4.7/inference.
