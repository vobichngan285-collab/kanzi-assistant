# 蓝星向导 v1.0.70｜智谱图文 OCR 速度专项实验

## 基线与目的
- 只在原仓库 `vobichngan285-collab/kanzi-assistant` 的 `exp/glm-ocr-speed-20261121` 分支实验。
- 基于已发布 v1.0.69：`5206ad1c2688c215e0dcfedf55785f4b0de01907`。正式千问3.7、手机/USB/C110取图、TTS、原有智谱 Chat/SSE/GLM-OCR Layout 及用户 API Key 不重新实现。
- 11月21日上午同类手机摄像头测试：智谱 FlashX 首句尚可，高精度 GLM-4.6V 完整生成很慢。早期文字到达与生成结束之间的尾段可能耗时数秒乃至十多秒。服务商输出时间不能仅凭本机代码判断原因。

## 这次实际改动
1. **官方智谱 GLM-4.6V / GLM-4.6V-FlashX / GLM-4.6V-Flash**：仅在“朗读文字”默认任务、默认提示词、Chat Completions 图片 OCR 识别时，将原提示词替为更明确的“直接逐行抄录、每行换行、不加无关文字”的简练实验提示词，尝试减少冗余生成和首行等待。不改变用户编辑过的提示词；不是所有云端服务商的通用变更。GLM-OCR Layout Parsing 不走该分支。
2. **GLM 图文 OCR HTTP keep-alive 尝试**：仅在服务端成功返回、完整读取并通过文本校验后，不主动断开 HTTP 连接，允许 Android/Java 默认 HTTPS 连接池尝试复用；任何失败/中断、其他任务、千问、其他服务商沿用原 `disconnect()`。是否实际重用连接取决于 Android HTTP 实现及服务端，不能保证提升。
3. **性能诊断**：智谱官方 Chat 成功 OCR 时，增加仅数字的 `cloud.output_chars` 和 `cloud.after_first_text_ms`，用来区分“首次返回已很快”与“生成剩余文本很慢”。不记录图片、文字、Key。
4. **未改**：相机/USB/C110的真实取图、SSE逐行朗读器、微软/广荣本地 TTS、grtts、忙碌锁 `cloudBusy`、单线程网络任务、1.5秒防误触、所有旧千问模型及百炼请求参数、用户已有配置、包名与保益启动器。

## 风险与回退
- 精简提示词有可能使识别内容分行方式变化或漏掉少量文字，故本版明确为实验版；不能以总响应变短为唯一成功指标，要逐行核查原文有无遗漏。
- Java keep-alive 只是**尝试**复用连接；若服务端主动关闭或数据未彻底消费，可能没有加速。保留 v1.0.69 Release 作为随时可回退的完整源码/包。
- 不能盲目解开 `cloudBusy`：单线程网络+手机TTS/任务历史关联需要配套解决并发、请求取消、过期结果问题，本版继续原逻辑，不宣称连续拍照卡顿已解决。
- 原调试包名 `com.vobich.bluestar.c110plusquick159` 不变；如设备因为签名不一致无法覆盖安装，先备份 API 配置，不可直接卸载造成密钥和任务数据丢失。旧包/Release保留。

## 真机验收：只做速度 A/B
- 使用同一机位、同一段可辨认文字与同一拍照分辨率，依次对比 **v1.0.69 与 v1.0.70** 的 `glm-4.6v-flashx`、`glm-4.6v` 各 5 次，并保留千问 `qwen3.7-flash` 作为不变基准。
- 选择 OCR“朗读文字”、C“快速逐行”、智谱SSE开启；若用过编辑后的提示词，实验策略不会更改该提示词，需要恢复默认后才能观察默认提示词优化，但勿未经用户同意覆盖其设定。
- 重点记录：`cloud.first_text_ms`、`cloud.first_speakable_ms`、`cloud.network_ms`、`cloud.output_chars`、`cloud.after_first_text_ms`、`capture.total_ms`，以及用户**实际听到首声**的体感。记录 429 / 其他HTTP错误率。
- 对比图片完整文字及阅读顺序，**不能**为缩短耗时截断文本；如新版本更快但漏字增多，判定实验失败。
- CI只检查静态范围、Java测试和可安装APK，并不等于真实供应商API、声卡首声或性能测试通过。
