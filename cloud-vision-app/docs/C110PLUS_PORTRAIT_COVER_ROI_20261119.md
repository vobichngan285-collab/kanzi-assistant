# C110+ v1.0.49：官方式竖屏铺满 + 所见即OCR ROI（2026-11-19）

## 用户明确目标与纠错
用户提供官方 SJCAM Zone **竖屏视频预览**截图，并指出 v1.0.48 强制旋转到横屏是错误理解；要求“像官方那样竖屏铺满画面，保留必要控件”，已明确授权“现在改”。本实验只修正 C110 专页“全屏”呈现与其 OCR 实际取景范围，**不更改**原厂 Wi-Fi/OEM 指令、LibVLC 3.6.5 单实例/150ms 缓存、1001 单张快门、9011/9038、云端模型/TTS/USB/手机预览。

## 改动
- 基线：此前成功构建 v1.0.48 的独立分支 `exp/c110plus-zoom-roi-fullscreen-150ms-20261119` / HEAD `cf7d525d8e5d92ab93ebad08de719feed5e44f18`，本版隔离于 `exp/c110plus-portrait-cover-roi-20261119`。
- 新版本 v1.0.49 (versionCode 58)，新 applicationId `com.vobich.bluestar.c110plusportrait149`；不覆盖旧 APK。
- C110 专页点击“全屏”后**保持竖屏**，不调用 `setRequestedOrientation`，也不重新打开相机/LibVLC。扩宽同一 `VLCVideoLayout` 到按 16:9 视频计算的自然宽度，让已有 `FrameLayout` 横向居中裁切；既不把 16:9 视频拉伸成 9:16，也不扭曲文字。保留顶部必要按钮、底部“高清拍照”及手动缩放、退出键；不隐藏 Android 系统栏。
- 默认普通模式继续原完整画面/1x 原始高清 JPEG 直接上传；**进入竖屏铺满后 1x 已是裁切后的中间竖幅区域**，OCR 因而必须裁同一区域，不能错误地继续上传整张 JPEG。手动 2x/4x 再在可见区域基础上做中心裁切，均复用 `C110ZoomGeometry.centeredCover` 坐标。
- 视频点击实时 OCR：`PixelCopy` 读取原视频 Surface 后按横向中心/viewport 宽高比+手动 zoom 裁到同一区域，压成 1 次 JPEG 请求云端。高清拍照：仍是原厂 1001 拍摄完整 JPEG/保留相机 SD 原图，**只在云端提交前** `BitmapRegionDecoder` 只解码可见 ROI 及 JPEG92 编码。若裁切失败，不得伪装成功上传整幅。画面与 JPEG 视角可能存在差异，需真机对照。
- 主页内联 C110 预览、USB、手机路径未改动；`C110LivePreview` 缓存仍 150ms，C110 专页仍 150ms。
- C110+ 的 `4003` 删除未实机验证，入口保持隐藏；不新增相机尺寸写入、不自动删图。
- 自动测试包含 portrait 9:16 的 1x/2x ROI 和相机 8M 素材坐标映射，回归原 20M/10M/8M/RTSP 的手动缩放测试，确认无横屏强制旋转和稳定 150ms 单实例；APK CI 成功仅代表编译，不代表真机成功。

## 真机验收
1. **不要旋转手机**：进入 C110 相机页、全屏按钮，确认竖屏铺满；顶部和底部可操作、文字与物体比例不变。
2. 使用居中印刷文本做 1x→2x→4x 测试；全屏 1x 只能识别竖向视野中的文字，返回普通模式 1x 恢复全幅。
3. 在全屏模式拍一张，验证原厂单次 1001、相机 SD 原图完整，上传 OCR 对应竖屏视野；退出全屏返回原来比例。
4. 多次切换全屏/普通确认没有 VLC 黑屏/重连、没有意外 1001 快门、150ms 稳定。不同的 RTSP/高清照片视场角需要实图复核。
5. 新独立包需要重新配置可用百炼 API Key；部分 OCR 模型免费额度可能耗尽（HTTP403 不应误判为播放器故障）。
