# C110 预览延迟独立对照实验｜2026-11-19

## 原则

- 原项目 `kanzi-assistant` 的 `main`、RC25、v0.1.20 OEM连接程序、已验证的C110 mini播放器均保持不动。
- 此包仅保留原 mini 的 `3012→3016→3001/par1→2015/par1` 启流及 `rtsp://192.168.1.254:554/xxx.mp4`、LibVLC 3.6.5 + VLCVideoLayout，原有300ms延迟play、固定codec和音频关闭保持一致。
- 只改变 LibVLC **network-caching/live-caching** 这两个成对参数。固定 file-caching=300、sout-mux-caching=300。切换即释放并重建播放器；禁自动循环重试。绝不读取/写入相机照片、云OCR、麦克风、远程服务及固件。
- 单独 `com.vobich.bluestar.c110latency` 包。为了严格排除连接流程对实验的干扰，**本实验包不包含Wi-Fi自动连接功能**；请先把手机从家庭Wi-Fi切换到C110热点后再启动它。这个要求只限对照实验，正常蓝星使用v0.1.20原厂连接方式即可。
- App日志仅在运行内存中积累，最长约28k字符；点击「复制诊断」复制到剪贴板由用户自行粘贴，不主动上传或保存。

## 建议真机操作

1. C110开机并开启热点；手机在系统Wi-Fi中连接到C110（网关192.168.1.254），关闭不必要的后台播放；与相机保持相同距离，实验期间尽量不移动位置。
2. 启动独立实验包，默认300ms开始播放（成功基线）；**用眼观察连续画面15～30秒**，快速挥动手臂并选一个「标记体感延迟」。
3. 依次切换150ms、100ms、50ms、500ms，每档至少15～30秒；有卡顿/黑屏应记录，不能只追求最小缓存数。
4. 可用「自定义」输入50–1500ms整数进行复测；保留每档至少一次完整会话。最后点击「复制诊断」把文字发送到聊天。
5. 优先比较`Playing`与`Vout`事件耗时、`stats.displayedPictures/lostPictures`派生的FPS/丢帧增量、`Buffering`回调次数、`nonplaying_samples`、进程CPU单核口径、主观延迟。若stats API在本版原生LibVLC不可用，则FPS和丢帧会显示「未知」，不伪造。
6. **实验不直接测量 camera-to-glass 真实延迟**。摄像头编码及Wi-Fi重传也会增加滞后。判断“慢半拍”是否改善以一致动作下的直观对照为主；有条件可用另一台设备高速视频同时拍摄真实动作及手机屏幕进行严谨测量。

## 日志结构

- `SESSION cache_ms`：每次独立启动档位。
- `play_call_ms`、`Playing at_ms`、`Vout first_event_ms`：播放器及输出开始的事件耗时，**不是传感器到屏幕像素的延迟**。
- `SAMPLE`：每2秒记录播放器运行状态、若可用的显示FPS/丢帧增量、缓存事件累计、非播放采样次数、进程CPU时间。
- `SUMMARY`：该档运行时间、帧/丢帧增量、错误及播放器异常。
- `USER_OBSERVATION`：用户手动主观标记。它不是科学测量值，不应伪称毫秒级精确。
