# C110 4003 单文件删除：原厂 APK 证据与安全实验（2026-11-19）

## 来源：用户原厂安装包，直接分析原始 DEX

- 原始文件：用户此前上传 bdcc3db17ea0e26aecaf22bc01fe99be.apk，SJCAM Zone 6.7.3.16 (org.jght.sjcam.zone)。
- 从原生 classes5.dex 解析字符串表、类型/方法表、class_data、code_item 和关键 Dalvik 指令：
  - Lorg/jght/sjcam/zone/camera/LYCamera;->deleteMediaFile，code_off 0x18ad28（同步版）和 0x18bce4（异步版）。
  - 代码中 const/16 4003 -> LYCamera$Command.setCmd，后调用 LYCamera$Command.setStr。
  - 方法将以 http://192.168.1.254/ 开头的 URL 替换为 A:\，再将 / 替换为 \，经 StrUtils.getUTF8String 放入 str 参数。
  - LYCamera.getRequestUrl 使用 http://192.168.1.254/?custom=1 + Command.getCommand()，后者将 map 中每项拼成 &key=value。
  - 同步版执行HTTP，检查HTTP200并经SCResponse.isSuccess判断；异步版调用OkHttp callback。
- 该证据仅支持编写与原厂一致的 4003 **单文件**指令，不能证明用户当前标准C110固件已经执行成功；也没有任何远程实机访问。
- SJCAM X同系列 LyCamera.deleteMediaFile 的调用只是旁证，不能替代 C110 真机验证。

## 本次代码中的安全边界

- **默认自动清理关闭**。拍照、预览、朗读、启动时均不发送4003。
- C110独立预览页面用户主动点击真实1001高清快门后，按拍照前后目录增量找新JPEG；完整下载并校验JPEG头尾与宽高，才保留一个包含该新文件路径、长度、宽高的候选。不会缓存第二份照片。
- 点击「相机」→「试删刚才的高清原图（实验）」→再次确认不可恢复后，才执行：
  1. 从C110指定的Android网络只读3012，核实标准C110，排除 C110+、PRO；
  2. 只读3002，检查固件是否列出 Cmd 4003，未列出即停止，**不发任何删除写入**；
  3. 严格限定到DCIM下合法、无目录遍历/参数注入、已在单个原图目录中再次读到的JPEG；若原图不存在立刻中止；
  4. 将准确的单文件路径转成OEM A:\DCIM\... 形式并URL编码，发送恰好一次 /?custom=1&cmd=4003&str=...；
  5. 只读复核原图是否从目录中消失，最多三次读取；报告HTTP/Status/耗时，**不重试写操作**。
- 用户不确认一律不删除；新照片会清除旧候选。退后台不会持久保存删除候选。
- 不删历史图片、不遍历清理卡、不格式化、不批量操作、不上传相机原图、不记录具体文件名到诊断。
- 此版本刻意**不提供自动删除开关**，须先真机确认仅删本次照片，才能在后续版本考虑后台异步自动清理。
- C110拍照失败、未下载完整JPEG或尚在云端识别期间，不允许删除；操作完成后恢复原有播放器。
