# C110 画质专项 A/B 0.1.0
基线 v1.0.89 58963e56aaf772385979acea9d4a86949200f6e5，独立包名 com.vobich.bluestar.c110qualitylab，不覆盖正式版、不读取正式版私有设置。
真机反馈：12轮完整Surface JPEG 293005–354898 bytes，1260×2590，PixelCopy 0，OCR大字准确、小字较差。实际RTSP轨道分辨率仍未知。
A：原已成功的LibVLC 3.6.5 + 完整Surface PixelCopy，增加尽力读取当前视频轨道width/height（不可用则-1）和进程CPU单核占比估计。
B：先停止A，沿用3012→3016→3001/1→2015/1与绑定热点；同一RTSP地址、同版本libvlc.so另建纯内存输出player，使用软件解码选项及 libvlc_video_set_callbacks / libvlc_video_set_format_callbacks，RGBA回调保留宽高，不使用Android显示层、不手动缩放裁剪；点击后等下一解码帧至多2秒，只有成功的新帧才进入原JPEG100、云端、TTS；没有回退旧图。B故意不画实时预览（黑屏上有模式按钮和取图区域），先用A取景并固定相机，切换B后等5秒点黑屏一次，使用查看上传图核对实际识别JPEG。A/B不能同时连接相机。正式APP保留。
设置：首次独立安装需要在实验APP内配置相同云模型、API key、任务和语音，不能自动搬运私有数据。保持相同字体、距离、光照、1x、不移动相机；A和B各5次，记录识别正确字数/原文字符数、解码或轨道宽高、JPEG尺寸/字节、取帧与网络时延、进程CPU单核估计。CPU估计为本进程自启动当前播放器起的平均值，不是严格解码CPU；B无显示、软件解码，A有显示，不能据此直接断言哪个解码器效率高。若B无输出或色彩异常，记录失败，不声称已经获取原始视频。B回调尺寸不是相机传感器尺寸，源流仍有有损压缩；可再从RTSP SDP/SPS或原厂命令核实编码规格。两个模式使用同一云端客户端和模型。CI检查不代表相机真机已验证。
