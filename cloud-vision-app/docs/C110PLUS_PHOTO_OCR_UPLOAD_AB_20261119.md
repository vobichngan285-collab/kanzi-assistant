入口：原蓝星向导 → 模式选择 `C110 运动相机` → C110摄像页面上方「相机」 →「照片尺寸·取图·上传·OCR准确率综合实验」。

实验页选项20M/10M/8M/3M**仅标记原厂已手动选择的档位，绝不发送1002/任何修改相机设置命令**。用户在SJCAM Zone改变Photo Size后返回蓝星，可能需要允许系统Wi-Fi重连。实验使用已验证`C110WifiCamera.shootAfterLivePreview(this)`，针对每次用户手动点击最多一个`cmd=1001`真实快门：必须把相机切照片模式`3001/par0`再对比拍前/拍后的内存卡/DCIM列表；只下载唯一新JPEG，校验JPEG SOI/EOI、解码边界尺寸，记录JPEG原始宽高、文件字节、模式切换/快门/发现文件/下载/照片完成时间。**不进行任何客户端重缩放/重编码**，直接将同一个 `photo.jpeg` byte[] 交给`CloudVisionClient.recognize`。固定`qwen-vl-ocr`模型和`TaskCatalog.defaults()[0]`相同OCR提示词，OCR速度实验模式A（非流式，方便完整文本对照），手机移动数据`requireCellular`网络上传。每张只调用一次云端OCR，无AI评分、无静默重试。用户必须在当前独立App里配置自己的百炼API Key，不能从其他包共享机密。

### OCR准确率算法
用户自己粘贴标准参考文字（测试纸上实际**所有清晰可见**的文字）。同一张纸、相同光线、距离/角度，按4档至少各拍1次。纯 Java 实现 NFKC、小写、去除 Unicode 空格和标点（保留中文、数字、字母和其他符号），逐Unicode码点计算 Levenshtein 编辑距离。字符错误率 `CER=编辑距离/标准文字字符数`，显示 `max(0,100*(1-CER))%` 为“字符准确率”；未填写参考原文显示`unknown`，不能把它当100%。这是**定量字符匹配度**，不是AI的语义评分；测试材料只覆盖部分文字时结果可能明显偏低。OCR文字与正确原文只留内存，不写入匿名诊断或磁盘；仅用户手动选择才可复制OCR全文到系统剪贴板。

### 云端上传与检测
记录`实际JPEG width×height`、`JPEG原始字节数`、发送给CloudVisionClient的`byteIdentical`布尔值、Base64字节数**估算**、`request_write_ms`、`cloud_ms`、`first_text_ms`、`prompt_tokens`、`completion_tokens`和按用户点击计算的`end_to_end_ms`。`request_write_ms`包含建立连接与HTTP请求写入，不是纯蜂窝带宽传输时间，不能误报。`prompt_tokens`后端未返回时标记-1未知。通过按钮可查看**本次实际提交JPEG**的缩小屏幕预览，只为本机查看、不改已上传的原始JPEG。客户端**无法知道千问内部缩到多少像素**，不得宣称服务器使用全部像素。

日志最多32次实验，只有数值、不含JPEG、Wi-Fi密码、API Key、OCR文本或标准答案。可复制汇总给助手；不保存相机照片、不删除/格式化相机SD、不上传标准答案到云端（参考答案只在本机与返回OCR文字比较）。

## 用户实际操作
1. 在原厂 SJCAM Zone 相机的**照片尺寸Photo Size**选择20M。保持一张文字内容**事先已知**的测试纸，角度/距离/光线不变。
2. 回蓝星**实验版**，打开C110相机页面，「相机」→「照片尺寸·取图·上传·OCR准确率综合实验」；需要时先在新包设置百炼API Key；打开移动数据。选择标记20M并粘贴标准原文，然后点击「拍一张原图→OCR→自动统计」。
3. 每个档位（20M、10M、8M、3M）都到原厂App手动调整Photo Size，返回实验页先手动选对应标签，点击一次拍照。不能仅改实验页标签，实验页的选项不会更改相机设置。
4. 在实验页查看实际上传的JPEG方向/画幅、OCR返回的原文、真实像素、CER和耗时；点击复制数值诊断发来。不需要额外旧 v0.2.0 设相机参数实验包。
5. 如有网络失败/切回App后热点断开，先恢复C110连通状态再点击下一张；软件不会自动重拍。可能本次已留一张在SD卡。
