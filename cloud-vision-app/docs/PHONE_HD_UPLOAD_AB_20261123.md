# 蓝星向导 v1.0.81：真实800万高清拍照，三档云端上传尺寸实验
日期：2026-11-23；原仓库 `vobichngan285-collab/kanzi-assistant`，基线 v1.0.80 `ac287edbd352dd090e3e56fa7e8248c080bf4fe2`，实验分支 `exp/phone-hd-upload-ab-20261123`。

## 背景
用户同一手机、同一千问OCR实测：720P快速预览取帧的首次TTS回调13次平均约1.57秒；原生约800万高清模式13次约2.69秒。完整云端日志首次文字分别平均约532ms（7次）/2178ms（8次）；这提示高清大图可能增加传输、云端图像处理、等待，但不能区分网络与推理。用户授权仅改变**已经拍得原生高清JPEG之后的上传分辨率**，比较小字识别与首次朗读。

## 最小变更
- 手机Camera2仍使用真实 `TEMPLATE_STILL_CAPTURE`，从Camera2支持的JPEG输出选择最接近800万的档位，真机3712×2088≈775万像素；不从720P预览帧插值。
- 仅手机高清路径的 `PhoneStillJpeg.prepare` 使用 `PhoneStillUploadPolicy` 的三种像素上限：原图（默认，8000000），1440P（3686400），1080P（2073600）。按照原图宽高比等比缩小；非16:9则输出保持原纵横比，并非裁切/拉伸成16:9；不会放大。
- 新设置行位于“设置→相机→手机高清上传分辨率”，一台APK切换三档，SharedPreferences持久化，切换无需重启摄像头；默认原图与旧v1.0.80处理保持一致。
- 诊断 `camera.phone_hd_upload_mode`: 0原图、1=1440P、2=1080P；`camera.raw_*`仍是真实拍照尺寸，`jpeg.width_px/height_px/bytes`是真实上传图。
- 保留原图无旋转/镜像且不超过上限时的原JPEG字节；需要处理时沿用Android Bitmap旋转/镜像与JPEG质量90。真实相机JPEG原质量92不变。
- 除本实验UI、选择档位、PhoneStillJpeg和相应纯Java测试外，不改手机快速预览取帧、USB、C110及C110+、模型及提示词、Base64及HTTP固定长度上传、取消旧任务、TTS及密钥。
- UI旧“手机高清约1200万”文字改成“约800万”以符合v1.0.80实际基线。

## 真机验收
保持同一千问模型、朗读文字任务、相同场景/光线/网络，高清模式原图、1440P、1080P分别5次；建议三档交替以减少云端繁忙带来的波动。核实raw始终3712×2088、缩图尺寸与JPEG字节下降，比较云端首字、首段可朗读、TTS首次音频回调和耳听首次出声，同时逐字比对小字漏读、失真。出现旧任务取消而缺少完整云端耗时时不可当作一次完整测量。
回归：快速720P/1080P、USB预览、C110原生照片、连续新照片取消旧识别、正常TTS；打包测试不代表真机通过。切勿卸载现有debug APK造成Android Keystore云API密钥丢失。
